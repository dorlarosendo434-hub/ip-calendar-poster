# 全年月历系列控制

仅在用户要求全年、12个月或连续系列时读取。单月普通请求不需要加载本文件。

## 先锁定一次的决策

全年开始前只确认一次：年份、IP参考图和服饰策略。服饰策略有两种：

- `固定原穿搭`：12个月严格保留参考图的服装、帽子、鞋履和配饰，只通过场景、动作、光线与卡片装饰体现季节。
- `随月份换装`：保持脸、五官、发型、发色、肤色、头身比例、3D建模语言与核心识别物；上衣、外套、裙裤、鞋履及季节性穿戴物可变化。每月至少保留或合理转译一项核心识别物，不能把所有标志性元素同时换掉。

将选择写入当前系列状态，后续月份直接沿用，不要每月重问。用户中途主动改变策略时，从下一张开始执行，并说明系列一致性会发生变化。

## 固定项与月度变量

全年固定：

- IP身份、脸部结构、发型和角色比例
- 3D角色材质与渲染质感
- 上方场景、下方水彩卡片的双区域结构
- 水彩纸、自然毛边、柔和晕染、克制留白的卡片语言
- 七列星期结构、文字层级、周末与节假日强调逻辑
- 原始IP图始终作为第一人物参考

逐月变化：

- 场景、人物动作、情绪与镜头角度
- 卡片配色、边缘水彩装饰和上下区域衔接方式
- 季节植物、果实、天气、节令物件与生活道具
- 服装与季节性配饰，仅在随月份换装模式下变化

## 推荐生产顺序

1. 检查原始IP图并记录身份锚点、核心识别物和参考图不可见细节。
2. 一次性确认服饰策略。
3. 在跑图前建立并核验全年12个月的结构化日期数据。
4. 先生成1月冬季样张，检查人物身份、水彩卡片、冬季元素和日期排版。
5. 再生成7月夏季样张，检查换季、换色和可选换装后是否仍属于同一系列。
6. 两张通过后，锁定版式比例、卡片语言、字体层级、周末颜色及IP身份锚点。
7. 按月完成其余10张，每张单独验收，不一次生成拼图。
8. 全部完成后横向检查12张，避免动作、地点、道具、动物、服装或装饰出现无意义重复。

每个月都重新挂载原始IP图。已通过样张只能作为版式与材质辅助参考，不能只拿上个月成图继续生成，否则会产生累积漂移。

## 月度季节方向

- 1—2月：雪花、梅枝、松果、冬日灯饰、温暖室内与节庆点缀
- 3—5月：嫩芽、花枝、春雨、草地、蝴蝶与轻盈花园元素
- 6—8月：荷花、水波、树荫、夏果、海盐蓝与通透阳光
- 9—11月：桂花、稻穗、银杏、枫叶、柿子与温暖收获色
- 12月：雪景、松针、莓果红、冬日灯光与柔软织物

这些只是方向，不是固定物件清单。装饰必须轻量、位于卡片边缘或留白区，不进入日期网格核心区域。

## 日期生产路径

正式全年成品优先使用混合路径：

1. 图像模型生成人物、季节场景和无文字或低文字的水彩卡片底图。
2. 使用 `scripts/render_calendar_card.py` 将已核验的年份、月份、星期、公历、农历、节气和重要节日精确排入卡片。数据文件必须覆盖当月每一天，不能缺号或增加越界日期。
3. 渲染时读取每个月真实的4至6行日期结构，在预留底部装饰安全区后动态计算周行距；4行、5行、6行月份分别获得与内容密度相匹配的纵向节奏，不得共享一套固定行高。公历数字与农历、节气或节日文字在3072×4096成图中保持20px可见间距。
4. 合成后再检查日期区域没有上挤下空或底部大面积无效留白，文字也没有压住人物、纸张毛边和插画装饰；整体仍然像水彩文创卡片，而不是普通电子表格。

只有在当前图像工具能稳定排准完整中文日历时，才允许直接在生图阶段完成全部文字。任何路径都必须执行逐日校验，不能把“看起来像日历”当作日期正确。

## 全年验收

- 12张均为独立3:4竖版，不是拼图或九宫格
- 每张都能识别为同一IP，且没有逐月漂移
- 服饰策略从头到尾一致执行
- 四季差异明显，但水彩卡片语言、文字层级与整体品质统一
- 12个月日期、农历、节气和节日均分别核验
- 每个月的日期网格均按实际周行数动态排版，组内文字间距清楚，底部留白协调
- 人物动作、场景故事、主要道具和边缘装饰不过度重复
